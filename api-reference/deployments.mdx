The Deployments API lets you trigger and monitor builds of your Mintlify docs site. Use it to kick off a deployment from your CI/CD pipeline after publishing a new release — ensuring your docs always go live in sync with your product. You can also query deployment history and poll for build status to gate downstream steps in your workflow.

## Trigger a Deployment

Start a new deployment for a project. Mintlify queues the build and begins processing immediately.

```bash
curl -X POST https://api.mintlify.com/v1/deployments \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "projectId": "proj_xxx"
  }'
```

### Request Body

<ParamField body="projectId" type="string" required>
  The unique identifier of the Mintlify project to deploy. Find your project ID
  in **Settings → General** in the Mintlify dashboard.
</ParamField>

### Response

```json
{
  "success": true,
  "data": {
    "deploymentId": "dep_abc123",
    "status": "queued",
    "url": "https://docs.yourcompany.com"
  }
}
```

<ResponseField name="deploymentId" type="string">
  The unique identifier for the newly created deployment. Use this ID to poll
  for status or retrieve deployment details.
</ResponseField>

<ResponseField name="status" type="string">
  The initial status of the deployment. Always `queued` immediately after
  creation.
</ResponseField>

<ResponseField name="url" type="string">
  The URL where the docs site will be live once the deployment succeeds.
</ResponseField>

## List Deployments

Retrieve a list of past and in-progress deployments for a project, ordered by creation time with the most recent first.

```bash
curl "https://api.mintlify.com/v1/deployments?projectId=proj_xxx" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### Query Parameters

<ParamField query="projectId" type="string" required>
  The unique identifier of the Mintlify project whose deployments you want to
  list. Find your project ID in **Settings → General** in the dashboard.
</ParamField>

### Response

```json
{
  "success": true,
  "data": {
    "deployments": [
      {
        "id": "dep_abc123",
        "status": "success",
        "createdAt": "2024-01-15T10:30:00Z",
        "url": "https://docs.yourcompany.com"
      },
      {
        "id": "dep_def456",
        "status": "failed",
        "createdAt": "2024-01-14T15:00:00Z",
        "url": "https://docs.yourcompany.com"
      }
    ]
  }
}
```

<ResponseField name="deployments" type="array">
  An array of deployment objects for the project.

  <ResponseField name="deployments[].id" type="string">
    The unique identifier for the deployment.
  </ResponseField>

  <ResponseField name="deployments[].status" type="string">
    The current status of the deployment. See [Deployment Statuses](#deployment-statuses) for possible values.
  </ResponseField>

  <ResponseField name="deployments[].createdAt" type="string">
    ISO 8601 timestamp of when the deployment was triggered.
  </ResponseField>

  <ResponseField name="deployments[].url" type="string">
    The URL of the deployed docs site.
  </ResponseField>
</ResponseField>

## Get Deployment Status

Retrieve the full details of a single deployment by its ID, including build completion time and any error information.

```bash
curl https://api.mintlify.com/v1/deployments/dep_abc123 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### Path Parameters

<ParamField path="deploymentId" type="string" required>
  The unique identifier of the deployment to retrieve. Deployment IDs are
  returned in the `deploymentId` field when you [trigger a
  deployment](#trigger-a-deployment) and in the `id` field of the [List
  Deployments](#list-deployments) response.
</ParamField>

### Response

```json
{
  "success": true,
  "data": {
    "id": "dep_abc123",
    "status": "success",
    "url": "https://docs.yourcompany.com",
    "createdAt": "2024-01-15T10:30:00Z",
    "completedAt": "2024-01-15T10:31:45Z",
    "error": null
  }
}
```

<ResponseField name="id" type="string">
  The unique identifier for the deployment.
</ResponseField>

<ResponseField name="status" type="string">
  The current build status. See [Deployment Statuses](#deployment-statuses) for all possible values.
</ResponseField>

<ResponseField name="url" type="string">
  The URL where the docs site is hosted.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO 8601 timestamp of when the deployment was triggered.
</ResponseField>

<ResponseField name="completedAt" type="string">
  ISO 8601 timestamp of when the build finished, either successfully or with a
  failure. `null` if the deployment is still in progress.
</ResponseField>

<ResponseField name="error" type="string">
  A description of the build error if `status` is `failed`. `null` for all
  other statuses.
</ResponseField>

## Deployment Statuses

Every deployment moves through the following lifecycle:

| Status | Description |
|---|---|
| `queued` | The deployment has been accepted and is waiting for a build slot. |
| `building` | The build is actively running. Mintlify is fetching your content and generating the site. |
| `success` | The build completed successfully. Your docs are live at the deployment URL. |
| `failed` | The build encountered an error. Check the `error` field for details. |

<Tip>
  To gate your release pipeline on a successful docs deployment, poll
  `GET /v1/deployments/{deploymentId}` at a reasonable interval (for example,
  every 10 seconds) until `status` is either `success` or `failed`. A typical
  build completes in under two minutes.
</Tip>
